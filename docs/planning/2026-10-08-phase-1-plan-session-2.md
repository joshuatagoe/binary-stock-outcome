Cost: every place and cancel is a signed transaction with a fee (play SOL on devnet). Whose on-chain book is Q1 | spec, user |
| D21 | **We build our own minimal order book inside our program** (user, 2026-10-07; spec p4 offers this as "more ambitious, but demonstrates deeper understanding"). Why: the existing ones are unmaintained (Phoenix, OpenBook) or can't be stopped at 4 PM (Manifest), and the spec says to justify every major dependency. Cost: the most build and test effort in the project. **Design lessons for Architecture.md** (not decided here): keep the book and each trader's balances in one account, as Phoenix and Manifest do, so a fill never needs the maker's own account (64-account limit); put a per-order match limit on how many orders one trade can fill; **a resting order locks what it offers when placed** (a sell locks the Yes tokens, a bid locks the USDC, e.g. "buy 10 at $0.54" locks $5.40), so no order on the book is an empty promise and a fill can't fail for lack of funds; the book account is created by the client and zero-copy, because Anchor `init` caps at 10,240 bytes; enforce the close time on-chain and refund resting orders after close (Q4). Keep it **minimal** (the spec's word): limit orders, cancel, match limit, close at 4 PM, admin pause; no fancy order types. **Why not Manifest (user challenged, 2026-10-07):** (a) **spec p9 requires "Pause / Unpause: admin can pause minting and trading"**, and Manifest has no admin or pause instruction, so we could pause minting (our code) but not trading (CONFIRMED instruction list); (b) its only stop is a per-order expiry counted in blocks, not time. Devnet blocks ran 0.235–0.243 s over 30 min (measured), so guessing "the 4:00 PM block" drifts ~2 min per hour of lead time (~14 min from 8:30 AM, computed), and orders placed outside our UI need not carry an expiry at all, so stale orders can be picked off after 4:00. For Manifest: live on devnet (RPC-checked), maintained, ~0.007 SOL per market, ~1,010 CU per order, battle-tested. Matching is the riskiest code to write ourselves. **Fallbacks if time runs short (Architecture decides):** Manifest (document that pause is UI-only and the stop is approximate) or OpenBook v2 (`time_expiry` + admin gate meet the spec, but it's unmaintained and ~1.9 SOL rent per market, ~93 SOL/day, refundable, against a devnet faucet of 2 requests per 8 h) | user, spec |
